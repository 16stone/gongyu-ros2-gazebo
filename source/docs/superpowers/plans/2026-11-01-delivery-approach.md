# 交付区接近互斥与泊位净空

目标：修复phase38中R1、B2同时接近D后互相阻塞、R1 Nav2 ABORTED的物理执行问题。保留12/14、实际扫描、近景和失败终态。用户已授权跑通项目，课程报告暂缓。本计划不改图策略、报告规则、任务期限、车速或既有冻结结果。

证据：B2的L→D请求147.444s，目标(1,.8)；R1的W→D请求203.682s，目标(.2,.8)。末态两车相距约.48m，均多次Failed to make progress。旧D网格间隔.8m，在两台车的定位/到位误差和PeerStop包络下没有足够稳健净空。不能关碰撞监测、放宽到位或把ABORTED改成功。

实现：新物理发展卡显式开启D接近互斥。长绕行边允许同时行驶，只在最后接近段按实际就绪顺序FIFO排队；E→W在通道中点后的出口段申请，并保持同一占用直至W→D真实成功且连续驻留结束，防止车停在W干扰D来车。D→W离开者不申请该入口。不是在长L→D边开始即独占，从而避免把整个绕行串行化。

接口：MoveDispatcher.begin新增可选arrival_region/arrival_gate_before，默认无互斥保持旧行为。PhysicalWorld仅在题卡声明physical_arrival_mutex_nodes时传递；构造器接收release_arrival回调，只有真实到达D的确认完成才释放。原3参数调用兼容；等待不出队、不伪造到位，失败保留资源并安全结束。

新卡D六泊位为两列x=1.2/-0.15、三行y=0/±1.35；初始模型/地图由卡重建，旧场景不覆盖。最小1.35m间隔对当前独立.25m误差、同伴半径与PeerStop旋转包络留正裕量，最西泊位距墙.85m。所有其他节点、原任务/期限/名义边时间保持不变，新的额外路程与排队误差保留为发展结果，不宣称是单因素GPU比较。

1. 写失败测试：两个接近者FIFO，等待者尚未提交末段；时间不能释放；E→W与W→D占用连续；真实D驻留后才放行；其他区域/空中动作并行。
2. 最小实现两个执行类及ROS接线，运行相关回归并检查旧无配置行为；整分支一次独立审查。
3. 冻结新卡/场景/源码/观察代码，GPU下一次400s发展运行，保存原生截图/实际RGB录像/独立审计/全部失败。不得根据回合中结果改输入。
4. 图模型策略保持dc522e2及其18+9未调参结果；仅物理适配代码改变，来源核对需明确组件版本，不能冒称旧物理回合使用了新接近互斥。
