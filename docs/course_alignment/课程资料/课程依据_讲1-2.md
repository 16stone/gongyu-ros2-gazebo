### 2.3 第 5 题：环境感知主流传感器（slide104–128）

- **slide104**：「UGV 的环境多变和地图数据不准确，不能只依靠单一导航方法（如 GPS）。必须利用传感器规划和跟踪一条路径……必要时检测和避开障碍。」
- **slide110**：传感器对比表（激光雷达 / 毫米波雷达 / 摄像头 / GNSS-IMU；远距离测量能力、分辨率、低误报率、温度适应性、不良天气适应性、灰尘/潮湿适应性、低成本硬件、低成本信号处理）。
- 逐类传感器：
  - **slide111**：激光雷达（LiDAR），「测量精度可达厘米级」。
  - **slide112**：「激光雷达还可以联合 GNSS/IMU 与高精地图等手段进行加强定位……结合车辆初始位置进行空间变化，获取基于全局坐标系下的矢量特征。」
  - **slide113–114**：摄像头（视觉传感器），「识别行驶过程中的车辆、行人、障碍物、交通标志等」「实现全部自动驾驶功能至少安装 6 个以上的摄像头。」
  - **slide115–116**：毫米波雷达，频率「10～300GHz」「测距和测速原理都是基于多普勒效应」「穿透雾、烟、灰尘的能力强」。
  - **slide117**：超声波雷达，发射「40kHz」超声波，「对温度敏感」「超声波散射角大，方向性较差」。
- **slide122–125**：感知信息处理器，计算平台方案「基于 GPU 的、基于 FPGA 的、基于 DSP 的计算平台方案」。

### 2.4 第 6 题：导航定位方法（slide129–154）

- **slide129**：「导航定位通过全球定位系统（GPS）、北斗卫星导航定位系统（BDS）、惯性导航系统、激光雷达等，获取 UGV 的位置和航向信息。」三类：
  - 「绝对定位：是指通过 GPS 或 BDS 实现，采用双天线……」
  - 「相对定位：是指根据初始位姿，通过惯性导航获得加速度和角加速度信息，将其对时间进行积分……」
  - 「组合定位：是将绝对定位和相对定位进行结合，以弥补单一定位方式的不足」
- **slide130–134**：卫星导航定位（GPS/GLONASS/BDS/Galileo；GNSS 定位「基于坐标系统和时间系统」；「基本三角定位原理」；差分 GNSS「伪距差分、位置差分、RTK、载波差分」）。
- **slide135–143**：惯性导航定位（INS「属于一种推算导航方式」；IMU「高频率更新……频率可达到 1000Hz」；GPS 10Hz + IMU 100Hz → 100Hz 定位输出见 slide139–141；优缺点见 slide143：「隐蔽性好」「定位误差随时间而增大，长期精度差」）。
- **slide144**：激光雷达定位；**slide145–146**：多传感器融合定位（贝叶斯推理、D-S 证据理论、卡尔曼滤波等）；**slide147–151**：高精度地图制作-SLAM；**slide152–154**：导航定位需求与研究方法（「评估的要求：导航、路径规划、感知与通信之间相互关系必须是系统级上评估试验。」slide154）。

### 2.5 第 7 题：360 度全车相对导航定位与传感器布设（关键差异页）

- **slide118**（传感器布设方法）：「无论是在白天还是夜晚，都能实行 360°监控，视野面积可达 3 个足球场。」
- **slide119**：「视觉传感器系统：配备了 8 个镜头，具有 360°视野，在长距离、日光和低亮度的情况下也能很好地工作」；激光雷达系统分「高频率的短程激光雷达；高分辨率的中程激光雷达；长距离激光雷达」。
- **slide120**：「任意方向都被至少 3 个传感器覆盖」「前后左右方向被至少 5 个传感器覆盖」「这种多层传感器系统可以无缝协同工作，绘制出整个视野的 3D 图像」。
- **slide121**：「会在前后方和四周布置激光雷达、毫米波雷达、视觉传感器、超声波传感器等……需要确保足够的数据冗余」。

### 2.6 第 8 题：全局与局部路径规划（slide155–170）

- **slide155**：「路径规划模块需要根据局部环境感知、可用的全局车道级路径、相关交通规则，提供能够将车辆引导向目的地的路径。路径规划可分为全局路径规划方法、局部路径规划方法和混合路径规划方法三种。」

## 三、课件原理 → 我们项目可检验的设计问题 → 可用证据类型（10 条）

> 本项目＝题目二「共域」课程设计报告（面向多域/异构无人系统的协同设计与验证）。
> 每条均注明：讲次 / 题号 / slide 号 / 原页关键句（简短摘录）。

1. **总体设计流程可追溯性**（讲一 / 第 5 题 / slide81、83、85、93）
   - 原页关键句：「设计流程有四个相互依赖、反复迭代和递归的流程。」（slide81）；「工程性需求 + 约束条件 = 顶层需求」（slide83）；「将用户需求转化为问题的定义，然后转换成认定的技术需求完备集。」（slide85）；「需求按照层次结构分解……直至完成完整的技术需求设计。」（slide93）
   - 可检验设计问题：共域系统的顶层需求能否逐层分解到功能/性能/接口/可靠性/安全性需求，并建立"用户需求→技术需求→功能→验证"全链路追踪矩阵？
   - 可用证据类型：需求追踪矩阵（RTM）、需求分解树、设计评审记录。

2. **技术需求完备集的六类覆盖度**（讲一 / 第 5 题 / slide86、88–92）
   - 原页关键句：「功能需求……性能需求……接口需求……可靠性需求……安全性需求……其他专业特性需求」（slide86）；「量化定义系统的执行能力：阈值设定或者需要的控制基线水平。」（slide88）
   - 可检验设计问题：共域方案是否逐项覆盖功能/性能/接口/可靠性/安全性/环境需求，且每项有可量化阈值？
   - 可用证据类型：需求规格说明表、指标阈值表、需求覆盖检查单。

3. **自主能力分级定位（中级/高级）**（讲一 / 第 1 题 / slide36）
   - 原页关键句：「中级：具有自主的感知和交互，学习、推理和决策以及执行能力；」（slide36）；「高级（智能）……且能够通过学习不断提高推理和决策能力」（slide36）
   - 可检验设计问题：共域系统中各域平台的自主等级如何声明与证明？能否给出"中级"所需感知—学习—推理—决策—执行五要素的可观测证据？
   - 可用证据类型：自主等级自评表、行为状态机、决策日志、演示视频。

4. **集群智能的协同增益**（讲一 / 第 4 题 / slide68）
   - 原页关键句：「集群以集群替代机动、数量提升能力、成本创造优势的方式，具有复杂/恶劣环境适应性强、系统间协同工作能力强、智能化程度高」（slide68）
   - 可检验设计问题：共域多平台协同相对单平台的性能增益（覆盖率、鲁棒性、任务完成时间）是否可度量？
   - 可用证据类型：对照仿真实验数据、消融实验曲线、协同/单机对比报告。

5. **GNC 概念边界与闭环**（讲一 / 第 9 题 / slide118–120、158）
   - 原页关键句：「导航……提供航行体的导航参数，如位置、速度、姿态等；制导……控制引导载体到达终点的过程」（slide118）；「制导控制系统：航迹规划及跟踪控制、自动寻的控制」（slide158）
   - 可检验设计问题：共域平台的导航—制导—控制三模块接口是否清晰、闭环是否闭合、责任是否可分离验证？
   - 可用证据类型：GNC 框图、接口定义、数据采集与回放、控制闭环测试记录。

6. **任务规划与载荷的耦合/模块化**（讲一 / 第 10 题 / slide164、165、177）
   - 原页关键句：「任务载荷……是无人系统的核心部分，在无人系统总体设计中起主导作用。」（slide164）；「任务规划……根据……携带任务载荷的类型……制定运行路线并进行任务分配。」（slide165）；「载荷设计的模块化和通用化……快速更换传感器」（slide177）
   - 可检验设计问题：共域任务分配是否随载荷类型变化而可重配置？载荷更换后任务规划能否在线重规划？
   - 可用证据类型：任务—载荷映射表、换装测试记录、重规划仿真截图。

7. **A→B 自主行为与战术行为完整性**（讲二 / 第 3 题 / slide39–40）
   - 原页关键句：「军用 UGV 系统的普遍自主行为即 A 点到 B 点的自主运动（机动）……战术行为应该包括：1）地形推断……2）军事机动」（slide39）；「3）灵活性……4）自我保护……5）……战术通信要求」（slide40）

   - 可用证据类型：场景化测试脚本、行为触发日志、A→B 全程轨迹与事件标注。

8. **360° 感知布设与传感器冗余**（讲二 / 第 5、7 题 / slide118–121）
