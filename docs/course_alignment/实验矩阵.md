# 实验矩阵（预登记；阶段 A 冻结，结果出来后只补证据路径）

## 0. 固定输入与变化因素的总约定

- 所有实验均写 `runs/<backend>_<scene>_<variant>_<nn>/`，含：版本与命令、场景/配置哈希、随机种子、实际开关、原始事件、指标、退出/关闭回执、必要时的真值轨迹与传感器片段。
- 固定：场景几何版本、任务卡（14 项及期限）、策略 P3、消息延迟 1000 ms、调度 100 ms、仿真步长 100 ms、随机种子（除显式扫描）、控制器与裁判代码版本。
- 只改矩阵中“唯一变化因素”一列；规则组合作用用明确因子组合。跨平台只比较行为能否复现，不把 Webots 秒数与 Gazebo 秒数混算。
- 关键重复：每个处理 3 次独立重启（种子 0/1/2 事先确定）；留出布局在规则和参数冻结后才跑。
- 时间口径：仿真时间（Webots 仿真时钟）、墙钟（运行器记录）、窗口余量（期限减实际交付时刻）分别标注。

## 2. 预登记留出场景 `web_holdout_v1`

- 与 `web_medium` 相同的任务语义（14 项及期限）、策略、控制器、规则和随机种子；只在布局层改变：中央通道两侧泊位错位、一条外侧绕行路线增长，低矮障碍位置移动到另一段原路径上。
- 目的：检验在见过场景选出的规则是否依赖具体几何；禁止用留出结果回头调参再报同一组数字。
- 期望：硬任务按期完成、无冲突；允许局部等待增加，但必须解释资源时间线与交付余量。

## 3. 负结果处理规则

实跑失败按预先验收口径统计，不得静默丢弃。每次失败记录：现象→日志定位到的层（版本/依赖/图形/仿真时间/坐标/设备/控制/规划/任务）→最小复现→修复→同条件复验→是否纳入选型。仍无法闭合的项进入交付验收说明的“仍缺证据”。
