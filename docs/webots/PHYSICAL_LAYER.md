# 物理执行层诊断记录（Webots 真实电机分支）

本文记录把「运动学后端」换成「真实电机驱动」之后遇到的每一个根因、判定证据、
最小复现与修复状态。单独成文，是因为这一层的问题不属于任务逻辑，
而属于平台移植、接触模型与传感器安装；混进正文会掩盖主结果的可靠性边界。

## 0. 这一层要回答什么

任务逻辑（谁先过通道、报告是否在有效期内、要不要改派）由独立裁判按冻结场景判定，
这条链在运动学后端已经闭合。物理层要回答的是另一个问题：
**同一套目标序列，换成真实电机和真实接触，能不能走完。**

两者不能混算。运动学后端的秒数与完成率只对任务逻辑负责；
物理后端若走不完，只说明执行器/接触/传感这一层还不到位，
不能反过来否定任务逻辑，也不能把运动学结果冒充成「真实执行器已验证」。

## 1. 已定位并验证的根因

### P1（已推翻）四轮矩形布局无法原地搓转

- **最初判断**：四轮滑移转向在等向库仑摩擦下，净偏航力矩随法向力同时增大而抵消，
  轮子空转、车身不转。
- **当时证据**：`phys-full-01`、`phys-full-02` 都在第一次需要转向时停滞。
- **复核后推翻**：`spin-pure-02` 强制 `omega=+0.8 rad/s`、`v=0` 连续 15.87 s，
  yaw 累计变化 **12.03 rad**（约 3.8π），位置漂移 **0.0 m**。
  底盘本身能转，停滞另有原因。证据见 `evidence/webots/phys-spin-02/summary.json`。
- **保留的结构性改动**：物理变体仍改为两驱轮 + 前后万向球。理由不是「四轮不能转」，
  而是两驱差速与控制器里的 `(v ± ωB/2)` 模型严格一致，减少了建模假设。

> 这是本项目里唯一一次「结论被自己的实验推翻」。保留在文档里而不删掉，
> 是因为它说明必须用隔离实验验证假设，而不能用整机失败倒推原因。

### P2 偏航符号冲突（两处叠加）

- **第一处：器件约定**。`spin-pure-02` 中 `omega=+0.8 rad/s` 对应
  `d(yaw)/dt = -0.758 rad/s`，即 `InertialUnit` 的 yaw 绕 +Z 顺时针为正，
  而控制器的世界航向是逆时针为正，故取 `theta = -imu.getRollPitchYaw()[2]`。
- **第二处：轮侧与 ω 的对应**。世界系为 +x 前、+y 左、Z 上；
  `omega > 0`（逆时针）时 `y=-0.17` 侧车轮的线速度为 `+0.17·omega`，
  必须比 `y=+0.17` 侧更快。历史公式给出相反结果，于是正 ω 实际产生顺时针转向。
  物理模式下差速项改为 `wl=(v+ωB/2)/R`、`wr=(v-ωB/2)/R`，约定恢复自洽。
- **验证**：`clear-pass-03` 单车依次到达 D(0.82)、W(1.82)、E(4.82) 三站，
  并在 `x=4.9519` 处真正触发 `channel_cleared`、随后收到 L 站指令；
  修复前同样条件下车辆无法沿 +x 稳定跟踪。
- **影响面**：只在 `GONGYU_PHYS=1` 生效；运动学后端的航向来自 GPS 位移方向，不受影响。

### P3 航向误差在 ±π 处不连续

- **证据**：`phys2wd-smoke-01` 中 `omega` 每 0.5 s 在 `+0.80` 与 `-0.80` 之间翻转，
  车身既不前进也不转向。
- **机理**：目标在正后方时 `atan2(sin π, cos π)` 因浮点噪声在 `+π` 与 `-π` 之间跳变。
- **修复**：`|err| > 2.85` 时按锁存方向取 `err = 2.85·sign`，
  `|err| < 2.60` 时才更新锁存符号。

### P4 机体碰撞盒底边离地只有 1 cm

- **证据**：旧物理模型 `boundingObject Box { size 0.42 0.40 0.22 }`，中心 `z=0.12`，
  底边落在 `z=0.01`。
- **后果**：车体稍有俯仰就触地，把驱动轮抬离地面；轮子照常转、车身不动。
- **修复**：碰撞盒改为 `0.40×0.34×0.14`（底边 `0.05`，与视觉体一致），
  万向球外移到 `x=±0.19`、半径 `0.035`，扩大支撑多边形。

### P5 到点判据与通道净空判据互相卡死

- **现象**：`clear-pass-01` 中车辆在 E 站「到位」后停住，裁判不再派下一站。
- **机理**：控制器按 0.18 m 泊位容差判到位，停在 `x=4.91`；
  而裁判要求 `x>4.95` 才认为通道清空，释放逻辑于是永远等不到。
- **修复**：物理模式改为按距离线性减速 `v = clamp(0.45·dist, 0.12, V_MAX)`，
  到位容差收到 0.10 m。`clear-pass-03` 因此在 `x=4.9519` 处正常清空。

## 2. 仍未闭合

### P6 走廊口 180° 调头夹墙

- **现象**：`clear-pass-03` 到达 E 后收到 L 站指令（正后方，需调头），
  车身在 `x≈5.0` 处反复小幅偏航，`th` 长期停在 ±2.9 rad 附近，位置不再前进。
- **机理**：走廊口墙体端面在 `x=4.95`，车身长 0.40 m；在通道口做原地 180° 回转时
  车体轮廓扫到墙端被夹住。这不是符号问题（P2 已修），而是**缺少倒车机动**：
  真实差速车需要先后退 0.3–0.5 m 再回转。
- **待办**：控制器加入「大角度误差时先后退再回转」的三段式机动，
  或裁判侧把调头点移到开阔区（`x>6.5`）。
- **状态**：未修。八实体整机因此仍不能宣称走完 14/14。

### P7 低矮障碍场景在物理上不可通行

- **几何**：障碍 `y` 尺寸 0.8、中心 `y=0.15`，覆盖 `y∈[-0.25, 0.55]`；
  通道半宽 0.6，可行空隙只有 `y∈[-0.60, -0.25]`，宽 0.35 m。
- **车体**：碰撞盒宽 0.34 m，余量 1 cm。
- **结论**：该场景在运动学后端「穿过去」，是因为裁判直接推进真值、不做接触；
  物理后端不可通行。这是**场景移植缺陷**，不是控制缺陷。
- **待改**：把障碍改为部分遮挡（例如 `y` 尺寸 0.5、中心 0.25），
  保留「探测到之后绕行」的原意，同时留出可通行空隙。

### P8 低位雷达安装高度等于低矮障碍顶面

- **证据**：`evidence/webots/b-scan-lowobs-0*/scan_stats.json`。
  障碍 `low_obstacle` 为 `Box { size 0.4 0.8 0.18 }`，中心 `z=0.09`，顶面正好 `0.18`；
  `lidar_low` 也装在 `z=0.18`。
- **实测**：低矮布局首次回波 `0.161 m`、500 ms 采样下有效命中 2 个样本，
  即可用预警时长约 **1.0 s**；开阔布局全部为 `9.90` 哨兵值、0 次命中。
- **后果**：扫描平面与障碍顶棱相切，只能拿到接触级回波，0.5 m/s 下约 0.5 m 反应距离。
  双扫描的「有/无」结论方向不变，但不能据此声称具备远程探测能力。
- **修复**：物理变体把扫描平面降到 `0.12 m`。
  已提交的运动学证据仍是在 `0.18 m` 下采集的，此处如实标注差异，
  不把修复后的能力回溯套用到旧回合上。

自旋隔离实验（只验证「能不能转」，不掺任务逻辑）：


单车物理全程（D→W→E，含通道净空）：

```bash

bash webots/tools/run_webots.sh web_b1_clear_phys clear-pass-03
```

`GONGYU_NO_RENDER=1` 只关闭主视图渲染：实测相机仍输出完整 160×120×4 图像
（`camera_bytes=76800`，逐帧签名变化），物理与控制器时钟不受影响；
整机 30 s 仿真由约 4 分钟墙钟降到 39 s。

## 4. 当前边界

- 物理变体世界为 `webots/worlds/*_phys.wbt`，由
  `GONGYU_WORLD_SUFFIX=_phys GONGYU_WORLD_PHYS=1 python3 webots/tools/generate_world.py`
  生成；运动学世界不受影响，`scene.sha256` 与已提交证据一致。
- `GONGYU_PHYS=1` 之外的分支行为不变，`R` 仍取历史值 `0.07`，
  使既有回合遥测可逐字节复现。
- **结论**：正式证据继续使用独立裁判的运动学后端。物理分支已能完成单车多站行驶与
  通道净空，但尚未完成整机 14/14，因此不把电机驱动写成已验收能力。
